### 完整性與隱私的固定規則

- 單筆／合併／跨區文件都要讀回**既有核定的**請款未稅、稅額、含稅總額、保留款、應收，不因 PDF 版型或議價折讓試算另算帳。
- 一般合併的原單各自保留案場及明細；跨區建商版必須只顯示**指定顯示區**。兩種本質不同，不能共用未驗證的扁平轉接器。
- 跨區建商版不外露原發票號碼、其他區名稱、員工抽成／薪資／銀行或登入資料；歷史保存文件可包含原發票對照，屬**不同的收件與分享權限**，不能誤寄建商。
- PDF 明細、施工彙總、備註、公司抬頭、大小章、頁界和可讀字體都不得隨意刪減；超出真正 A4 單頁時必須嚴格阻擋**新交付流程**，不能宣稱原生 File→Print 已被 DOM 控制。
- P40-12／P40-15 的議價／折讓仍是**唯讀試算**，沒有核准改帳、PDF 重算、分配折讓或修改發票與薪資。

## 3. 下一個「真正可執行的最小正式候選」規格 — **目前未授權建立/發布**

如要朝正式上線繼續，必須先決定唯一範圍，**不把 AH～AO 整串實驗分支直接合併**。初步建議：

**可選的第一個小範圍：** 以屆時最新正式 `main` 另開獨立**候選**，只針對跨區**現行一般對外** `billing-print.html` 的 `invoice-group-document` 在 print media 的非字級間距調整；保留原公司抬頭、章、區域與明細和彙總。這可以針對部分多明細文件減少頁數，但**不能**將「所有 PDF 保證 A4 一頁且安全阻擋」視為完成。

若真正需求是「對外只交付驗證過的 A4 單頁」，還須再**單獨設計 PDF-first 交付路徑**（例如由本機瀏覽器內部產出 PDF bytes，再由 PyMuPDF 等**獨立**來源驗證生成的那份檔案，或可信的 PDF 檢查服務），確保交付的是**同一份被驗證的 bytes**。不能用 DOM 高度、`window.print()` 的呼叫前旗標或 CSS 推斷頁數。既有授權／資料來源的讀取方式、印章來源、跨裝置同步與外部傳輸需要獨立安全設計，不得上傳整份 ERP 備份到外站或將發票、銀行、員工個資交給服務。

**目前不修改正式列印器，也不加入正式按鈕；** 不將只在 Chrome headless PASS 的測試 CSS 誤認成正式網站已上線。

## 4. 七項必須全部通過的正式發布門禁

1. **正式 SYNCED**：在實際正式 ERP 介面重新確認最新同步、沒有 `REMOTE_NEWER`／`UNKNOWN_CONFLICT`；本審查並未取得此真實狀態。
2. **完整可還原安全備份**：確認最新 IndexedDB、Emergency mirror、雲端資料及回復流程；本審查未讀任何真實資料、沒有觸碰／刪除備份。
3. **真實抬頭／LOGO／大小章**：真實建商版的文字位置、色彩、印章清晰及單頁都需核對，本研究只使用模擬章。
4. **電腦＋實體手機**：全部指定打印入口在正式設備驗證 PDF，不能以 390px 模擬手機代替。
5. **真正 PDF bytes 與所有入口安全**：證明交付的確切 PDF 已經驗證 A4、一頁、內容完整、原始來源及隱私；原生快捷列印／歷史版本必須明確區分。
6. **完整帳務回歸**：單筆／一般合併／跨區／歷史文件的請款、應收、保留款稅基、議價折讓唯讀、不同月原發票、薪資抽成、銀行流水，及客戶扣款都不得被改動。
7. **負責人明確正式發布授權**：從屆時最新 main 產生經安全檢查的最小候選；全部 CI、差異／備份與真實 PDF 驗收 PASS 才能提出發布。這一輪「下一步」不是正式發布授權。

**任何一項失敗或無法驗證，就停止正式合併／部署。**
