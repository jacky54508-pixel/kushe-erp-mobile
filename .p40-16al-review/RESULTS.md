# P40-16AL｜一般合併請款多原單 PDF 與對外隱私驗證

**DRAFT / SYNTHETIC ONLY / 禁止合併、禁止部署、禁止修改正式 ERP 資料**。本分支繼承前階段 P40-16AH～AK 的**隔離測試檔案**，只新增 `.p40-16al-tests/`、`.p40-16al-review/`、獨立 CI。無任何對正式主程式、原請款列印、雲端同步、Supabase／MFA、銀行、薪資、抽成或真實請款資料的改動。

## 1. 真正正式程式的來源

- `assets/js/billing-bundle-print.js` 的 `buildCombinedView(rows)` 只允許同客戶至少兩張單；回傳 `schema:'kushe-combined-billing-v1'`、`documentType:'combined-billing'`、`billings[]`（各含來源單號、案場、日期、施工列、稅別／發票狀態、原單未稅/稅額/總額/保留款/應收/備註）、`projects[]`、合併 `totals`。**不得**把所有來源攤平成一張假單筆。
- 正式 `billing-bundle-print.html` 會逐張來源原單顯示原始工程內容和區域彙總，最後顯示**合併請款總計**與簽章。其正式版本目前**沒有**本階段新增的「最下方施工項目彙總」區塊，因此本原型有一個**刻意新增的測試版區塊**，**不能**宣稱與既有 PDF 逐字逐像素相容。
- 合併請款並不是跨區合併到單一指定區的「對外隱藏其他區」流程。後者使用 `external-billing-print.js` 的獨立欄位和版型；**P40-16AL 不處理，也不改動後者。**
- 正式一般合併 PDF 目前會顯示對外發票**狀態標籤**；本階段測試版為降低洩漏，顯示來源稅別、但不呈現原始發票號碼或完整發票清單。這是隱私檢查與版型差異，仍須另外對外驗收。

## 2. 隔離 PDF 的實際產生流程

1. 在 localhost-only、僅裝虛構紀錄的測試網頁中載入正式**未修改**的 `billing-print.js` 和 `billing-bundle-print.js`，取得真正的公開合併 View；測試頁將公司名替換為中性的虛構公司，**不使用任何正式章印**。
2. `combined_contract.js` 只從已產生之 View 拾取對外白名單，對每張來源分別核對 `billingId`、單號、案場/日期、稅別、明細、原單核定未稅/稅額/總額/保留款/應收；再核對所有原單和合併總計的一致性。**不重新計算或覆寫正式核定金額。**
3. 施工項目彙總按**來源案場 ID + 品名 + 單位 + 單價 + 來源計價類型**分組，避免不同區域或不同計價來源被不當合併；所有原始戶別及明細仍逐張列出。
4. `combined_pdf.js` 透過瀏覽器 `pdf-lib` / `fontkit` 真正產出 PDF bytes；Python PyMuPDF 獨立打開，核對 A4 單頁、最低 8.1pt、來源單號/案場/日期/所有戶別、各原單金額、合併總計、最下方彙總、頁界、模擬 LOGO **18×14 mm**、模擬大小章 **54×24 mm**。
5. 發現缺漏、總額不符、跨公司、重複單號、區域不符、非 `SYNCED` 的**虛構信任狀態**、內部發票哨兵混入公開備註、長品名或長備註，均停止產生／交付；測試附件只包含通過的**虛構** PDF 與 PNG。中文字型僅由 CI 作業環境暫時安裝，結束刪除；不提交或提供字型檔。

## 4. 正式發布仍為 BLOCKED

本階段並**沒有**進行正式資料的逐筆財務核對、公司章影、既有 PDF 視覺等效、正式 MFA/SYNCED 信任鏈、實體手機列印，或發票歷史多月份對外流程的完整驗證。使用測試用 `approvedByTrustedCaller:true` **不表示**正式授權已通過；真實信任狀態/公司權限仍未整合。

**不能直接把草稿研究合併進 main**。任何後續正式候選應另由**當時最新 main**建立，只改最小功能範圍，確認最新 `SYNCED`、完整可還原安全備份、原請款所有模式、跨區顯示、保留款稅基、發票隱私、歷史修訂、原明細彙總、大小章實體手機與電腦對外 PDF，所有 CI PASS，並另得負責人**明確正式發布授權**。

## 5. 建議下一階段 P40-16AM

**只在另一隔離候選**查核「跨區合併到指定區對外顯示」的獨立來源與真正 PDF：應只顯示指定區、不帶其他區原單與內部多發票、保留原施工明細及底部施工項目彙總；正式 `external-billing-print.js` / `billing-print.html` 保持未變。跨區轉接器必須跟一般合併及單筆完全分開，不能共用一個未驗證的假資料格式。

**P40-16AL 結論：一般合併的虛構 A4 PDF 技術原型 PASS；正式 ERP 相容性與發布仍 BLOCKED。**
