# P40-16A — 議價／折讓正式入帳：唯讀前置設計與安全門檻

**狀態：開發分支、安全評估階段。** 不能正式入帳、不能修改實際業務資料，不載入正式站，也不修改 `main` 或 `beta`。

## 業務背景

- 現有 P40-15C 是單筆及合併請款的**唯讀試算**：核定金額、折讓總額、風險提示，不記錄折讓。
- 合併請款只是一份對外文件，兩張原請款及應收、發票、薪資／抽成仍有獨立來源。
- 使用者目前的合併請款案例：原總額 NT$632,100（未稅 602,000、稅 30,100），整張試算核定 600,000，差額 32,100；其中有 1 張來源已開發票。
- 這些數字是**業務需求背景**，單元測試只使用虛構的同金額資料，不導入實際資料。

## 建議的正式業務流程（各階段均須再獨立授權）

1. **原單關聯驗證**：保留每張原請款的不可變原金額、發票及收款來源。每張合併文件必須鎖定自身 ID、revision、完整來源快照及最新雲端修訂碼。
2. **議價核定紀錄**：填建商核定金額、核定日期、議價事由、文件／簽認依據；僅在核對完成後建立單獨版本化記錄，不覆蓋原請款。
3. **原單分攤**：對合併請款必須由使用者或會計明確核定每張原單折讓額、未稅、稅額、保留款及應收調整；不可默認按比例或任選第一張。
4. **發票／收款檢查**：逐張區分未開、免開、已開、作廢；已開發票應取得會計確認的折讓證據與稅務處理，歷史收款／支票／保留款不可被覆寫或自動沖回。
5. **員工抽成處理**：折讓是否影響未付款抽成、已付款抽成，必須制定獨立規則並以原單、員工、案場的唯一識別追蹤；不能憑合併金額直接重算薪資。
6. **擬入帳預覽**：顯示原總額、核定總額、每張分攤、發票憑證、應收調整、保留款、員工抽成影響，並提示阻擋原因。
7. **受控寫入（尚未實作）**：未來獨立 P40-16 後續階段才討論；需交易式寫入、操作唯一鍵、CAS／預期快照、不可變調整流水、重送去重、回沖（而非刪改原單）、權限與雙確認、備份及可回復驗證。
8. **正式發布**：僅在隔離測試、完整 CI、最新 SYNCED、可還原安全備份、最新 main 差異都通過且另行取得明確發布授權後考慮。

## P40-16A 實作

- `assets/js/p40-16a-concession-review.js`：純函式、唯讀、無副作用，要求明確確認原單與收款快照；檢查逐張分攤的算術一致性，偵測已開發票、收款、支票及其他折讓紀錄。
- `.p40-16a-tests/review.test.cjs`：全虛構測試；單筆、合併、金額、重複、快照變更、已開發票、付款、支票、原始 18 項明細不變等。
- `canPost=false`、`canSave=false` 永遠為真；不在 `index.html` 載入，不顯示任何入帳或儲存按鈕。

## 針對本次合併請款的安全結論

- 整張總折讓 NT$32,100 的**算術可先試算**，但**不可直接入帳**。
- 至少需核對其中已開發票原單的折讓憑證與稅額，並明確指派各原單折讓金額及應收處理。
- 原對外 18 項施工明細、原單、收款、銀行、薪資及抽成在 P40-16A 均保持不變。

## 停止條件

任何來源缺漏或重複、同步快照不同、應收/原單金額無法勾稽、分攤加總錯誤、重複折讓、發票/稅務證據不足、已收款超過折讓後應收、支票預留高於未收款時，一律禁止正式入帳。若未來採用合法的分期或部分折讓方案，也需另建立可稽核的分攤及餘額規則。

**此文件不是入帳授權、不是稅務憑證，也不是可以直接拿來更新正式 ERP 的程式碼。**
